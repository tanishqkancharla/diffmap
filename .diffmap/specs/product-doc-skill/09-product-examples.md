# Prove the product promise with real examples

The [funnel](05-shipping-funnel.md) needs evidence before the website asks anyone to install. This phase produces a small public-safe example set, not another runtime feature.

## Today

The existing website leads with diff review. The local skill proposal demonstrates authoring principles, but it is not a clean first-user proof across all three product-doc uses.

## Proposed

Use one real product journey to demonstrate an existing-system explanation, a plan, and a review of actual changes. Include a familiar UI action and a service responsibility. Keep each planned small change on its own page. Show diagrams where they clarify decisions and preview a real prose change; distinguish observed behavior from illustrative proposals.

Demonstrate a reader leaving comments, using Copy comments, and returning feedback to the agent. Explain that comments are browser-local. Select a supported public review format; local media currently blocks gist sharing, and unlisted links are not private access control.

## Acceptance

A reader unfamiliar with the code can explain the behavior, reason, and requested decision. Inspect diagrams and media, verify source links and document titles, and review every published file for private data. A second reader must be able to open the chosen share format. Keep a short feedback/revision example for the website and onboarding.

Depends on the local skill, not a published branded runtime. Feeds [the website](04-product-doc-website.md) and [onboarding](13-clean-onboarding.md).
