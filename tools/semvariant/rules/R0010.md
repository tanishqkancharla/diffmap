# Keep policy in rules, procedures in skills, and implementation facts at their source.

Rules express repository facts, constraints, and criteria for judgment. Skills own reusable workflows and tool operation. Link them rather than duplicating their procedures in rules.

Reference implementation sources for changing commands, schemas, versions, and architecture. Keep operational detail only when needed to apply a rule. Implementation specs own migration status; rule titles must not present planned behavior as shipped.

When a skill owns a workflow, make the rule a short trigger to load that source. Keep independent repository constraints in their owning rules.
